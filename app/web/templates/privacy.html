Privacy

DomainCheck keeps very little. This page says exactly what, and where the limits are.

The short version

  • ✓ No account, email address or password.
  • ✓ No database. Nothing is written to disk by the app.
  • ✓ Reports are held in the server's memory for one hour, then deleted.
  • ✓ One cookie, used only to protect the form. No tracking, advertising or analytics.
  • ✓ Nothing is loaded from other websites: no fonts, scripts, images or trackers.
  • ! Not private from anyone who has your report link, or from the hosting provider's ordinary request logs. See the limits below.

What happens when you run a check

You type a domain. Our server then looks at that domain from the outside, the same way any visitor or mail server could:

  • DNS lookups for its SPF, DMARC, DKIM and CAA records.
  • A few secure connections to port 443, to read the certificate and see which TLS versions it accepts.
  • One request for the home page over HTTPS and one over plain HTTP, to read the headers and cookie flags.

The site you check sees these requests coming from our server, not from you. They are labelled "DomainCheck" in the User-Agent. There is also an optional check that asks for a short fixed list of sensitive file paths (such as /.env). It is off unless whoever runs the server turns it on.

Who can see your report

Each report has a long random link that cannot be guessed. Anyone who has the link can read the report until it expires, so share it with care. There is no list of reports and no search.

Limits of this promise

  • Server logs. The server software and the hosting provider may keep ordinary request logs: time, IP address and the page address. A report's page address contains its private link. DomainCheck itself does not add your domain to its logs.
  • Public information. The checks only read what the domain already publishes. If a result worries you, assume others could see the same thing.
  • A learning project. It comes with no guarantees. Do not use it for anything that needs a formal privacy or security assurance.
  • Running it yourself. If you run your own copy, you decide where logs go and how long they stay.
